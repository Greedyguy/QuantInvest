# 백테스트 데이터 연결·품질 검사 — 직접 실행

수집 중에도 사용할 수 있는 **읽기 전용 검사 + 연구용 입력 준비** 단계다.
시세 API를 호출하지 않고, KIS 키·계좌번호를 사용하지 않으며, 전략이나 주문을 실행하지 않는다.

## GitHub 실행

QuantInvest → Actions → **백테스트 데이터 준비·검사 (직접 실행)** → **Run workflow**.

| 항목 | 기본값 |
|---|---|
| Branch | `main` |
| 비공개 데이터 버전 | `main` — 실행 시 실제 커밋 번호로 고정 |
| 평가 시작·끝 | `2025-01-01` / `2026-08-31` |
| 지표 준비 시작 | `2024-01-01` |
| ETF 포함 검사 | 켜짐 — 이름 기준 레버리지 제외 목록, 공식 배율 인증 아님 |

이미 설정한 `MARKET_DATA_REPOSITORY`와 `MARKET_DATA_REPO_TOKEN`을 사용한다.
별도 비밀키를 추가할 필요는 없다. 자동 예약이나 완료 감시를 등록하지 않는다.
수집이 아직 끝나지 않았으면 누락으로 차단되는 것이 정상이다.
2025년부터만 수집하면 2024년 준비 자료 부족도 표시된다. 이는 조건을 몰래 완화하지 않는다.

실행의 **Summary → 비공개 상세 보고서**에서 결과를 확인한다.
보고서는 `stock_rawdata`의 `validation/run-실행번호-시도번호`라는 새 브랜치에 저장된다.
수집이 쓰는 `main`에는 커밋하지 않아 수집 진행과 충돌하지 않는다.
재검사는 자동으로 이어지지 않으며 필요할 때 같은 버튼으로 실행한다.

## 결과 해석

- `blocked`: 파일 손상, 수집 요청 구간 누락, 빈 응답, 가격 날짜 누락, 지표 준비 부족 등.
  보고서는 저장하지만 백테스트 입력은 생성하지 않는다. Actions의 마지막 검증 단계가 빨간색이 된다.
- `review_required`: 구조적으로 읽을 수 있는 입력은 생성했지만, 수정 비율 변경이나 큰 수정주가 변동이 있어
  기업행동/가격 검토가 필요하다. 기본 읽기 함수도 이를 자동 승인하지 않는다.
- `ready_for_research_inputs`: 기본 검사를 통과한 연구용 입력. 전체 시장·기업행동·총수익·실전 운용 승인이 아니다.

검사 내용:

1. 종목 마스터와 원본 응답·변환 파일 SHA256, 종목 ISIN, 날짜 범위, 행 수.
2. 저장 원본 응답을 다시 해석한 결과와 변환 표의 일치 여부. 임의 가격 수정이나 원주가/수정주가 혼합 차단.
3. 종목·가격 종류별 요청 구간의 합집합을 이용한 미수집 기간. 빈 응답을 휴장일로 확정하지 않음.
4. KODEX 200 관측일 대비 상장일 이후 날짜 누락, 원주가/수정주가 날짜 불일치, 충돌하는 중복 가격.
5. 평가 시작 전 KODEX 200의 최소 120거래일과 지표 준비 구간. 신규 상장 종목은 별도 이력 조건을 만족해야 후보가 됨.
6. 거래 없는 날과 0원 시세 표시, 수정주가/원주가 비율 1% 초과 변화 및 수정주가 일변동 35% 초과 검토 표시.
   이 임계치는 이상 탐지 장치이지 주식분할 여부나 경제적 정확성의 확정 판정이 아니다.

누락 가격을 채우거나 이전 연구의 일부 종목 자료로 자동 대체하지 않는다.
달력은 KODEX 200 관측일 기준이며 독립적인 거래소 영업일 인증을 대신하지 않는다.
현재 종목 목록을 과거에 적용하는 생존편향, 과거에 수집된 수정주가 버전 부재,
주식분할에 따른 보유 수량 변환, 배당·분배금·세금은 별도 검증 대상이다.

## 기존 백테스트 코드와 연결하는 공통 읽기 함수

검사를 통과하면 보고서와 같은 폴더에 `bundle.json`, `raw-0000.parquet`, `adjusted-0000.parquet`,
`universe-0000.parquet`, `eligibility-0000.parquet` 등이 생성된다. 큰 표는 10만 행씩 분할하며
읽기 함수가 다시 연결한다. 데이터/코드 커밋 번호와 입력 해시를 보존한다.

```python
from backtest_market_inputs import load_backtest_inputs

inputs = load_backtest_inputs(
    '/path/to/private/report-folder/bundle.json',
    allow_provisional=True,  # 현재 종목 목록 기반 연구라는 한계를 명시적으로 인정
)
raw = inputs.raw                 # {종목: 날짜 인덱스 OHLCV/value 표}
adjusted = inputs.adjusted       # 동일 구조, 지표 계산용
calendar = inputs.calendar      # 준비 기간 포함
evaluation_dates = inputs.evaluation_dates  # 실제 수익률 평가 기간만
```

기본 로더는 **주식 + KODEX 200**만 반환한다. ETF 전략 실험은 `include_etfs=True`로 명시한다.
`eligibility`의 거래 가능 여부/최소 이력을 반영해야 하며, 당일 종가 기반 신호의 체결은 다음 거래일부터다.
0원 OHLC는 읽기 단계에서 결측값으로 바꾸고 앞날 가격으로 채우지 않는다.
기존 엔진에서도 거래 정지 중 평가 및 체결 정책을 별도로 적용해야 한다.
기업행동 검토 플래그가 있으면 기본적으로 로딩이 차단된다. `allow_action_review=True`는
명시적인 미검증 실험용이며 경제적 검증이나 운용 승인을 대신하지 않는다.

**여기까지가 데이터 연결 계층이다. 기존 11개 전략 실행/성과 비교 화면을 완성한 것은 아니다.**
기존 연구 실행기는 고정된 과거 파일과 검증 해시를 사용하므로, 후속 작업에서 이 공통 입력을
받는 실행기로 연결하고 같은 비용·원금·체결 규칙을 검증해야 한다. 운영 매매 코드는 변경하지 않는다.
