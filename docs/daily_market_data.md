- 현재 마스터로 수집하는 과거 가격이므로 역사적 상장폐지 종목 전체 복원을 뜻하지 않는다.

## 휴장일과 날짜

[KIS 공식 휴장일 조회 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/chk_holiday/chk_holiday.py)의
`CTCA0903R` / `opnd_yn`을 사용한다. 실행일 이전 14일이 응답에 모두 있어야 이전 개장일을 결정한다.
해당 날짜가 누락되거나 조회가 거절되면 평일이라는 이유로 개장일을 추측하지 않는다.
정상 응답은 날짜별 원본·해시와 함께 저장해 같은 날 재실행할 때 재사용한다.
공식 안내는 가급적 하루 한 번 호출하는 것이므로 날짜별 반복 조회나 페이지 전체 순회를 하지 않는다.

종목 목록은 **조회한 오늘 날짜**, 가격은 **이전 거래일**로 구분해 기록한다.
오늘 신규 상장되어 전날 가격이 없는 종목은 전날 가격 대상에 넣지 않는다.
향후 실전 선정도 결정 시점에 관측한 목록과 전일 가격을 사용해야 이 입력과 일치한다.
특히 다음 날 주문을 낼 경우 당일 종가를 쓰는 전략보다 데이터가 하루 늦다는 점을 백테스트에 반영해야 한다.

## 처리량 및 저장

기본 실행당 가격 조회 상한은 10,000회, 시간 제한은 4시간이다. 원주가/수정주가를 따로 받으므로
현재 약 3,900개 대상에 날짜 구간 하나당 약 7,800회가 필요하다. 다운로드 시간만으로도 수 시간 걸릴 수 있다.
90일 고정 구간 중 진행 중인 구간은 종료일이 바뀔 때 다시 받아 최근 정정값을 보존한다.
상한에 도달하면 검증된 중간 결과만 저장하고 입력 준비를 차단한다. 다음 실행이 이어받는다.
새 거래일 없이 같은 대상/기간을 재실행하면 가격 조각을 재사용한다.

기존 과거 수집과 같은 쓰기 대기열을 사용하며 진행 중 작업을 취소하지 않는다.
여러 수동 실행을 동시에 예약하지 않는다. GitHub의 동일 concurrency 그룹에서는 대기 작업이
더 새 대기 작업으로 대체될 수 있다. 수동 수집은 예약 시각과 겹치지 않게 실행하는 것이 좋다.
강제 푸시·리셋은 사용하지 않는다. 외부 커밋과 충돌하면 저장 실패를 숨기지 않는다.
수집 중 취소되면 해당 실행에서 아직 GitHub에 커밋하지 않은 조각은 남지 않을 수 있다.

모든 원본과 상태는 비공개 `stock_rawdata`의 `store/`에 저장한다.
공개 artifact나 공개 코드 저장소에 시세를 올리지 않는다.

- `calendars/`: 실제 수신한 휴장일 응답과 정규화 표.
- `masters/`: 날짜별 관측 종목 목록.
- `kis_segments/`: 재사용 가능한 원주가/수정주가 구간.
- `daily_inputs/`: 전체 대상의 전일 가격과 오늘 관측 목록을 결합한 입력 표.
- `daily_status/latest.json`: 최신 실행의 준비/누락/오류 상태.
- `daily_status/YYYY-MM-DD.json`: 실행 날짜별 상태.

## 종목 선정과 연결하는 읽기 함수

```python
from market_data_store import MarketStore
from daily_market_data import load_daily_selection_inputs

store = MarketStore('/path/to/private/stock_rawdata/store')
universe = load_daily_selection_inputs(store)
# 기본: 주식 전체 + 기준 지수 KODEX 200. 임의 상위 N개 제한 없음.
# ETF 실험에서는 include_unverified_etfs=True를 명시하고 상품 분류를 별도 검증한다.
```

현재 실행일의 `daily_price_inputs_ready` 자료만 반환한다. 누락 종목이 있거나 예산 부족/오류로
끝난 경우 예전 성공 자료로 대체하지 않는다. 입력 해시와 실제 사용 가능 시각도 확인한다.
거래가 없거나 0원 시세인 종목은 사라지지 않고 `tradable=false`로 남는다.

이 함수는 원주가·수정주가·ISIN·종목 분류·거래 가능 여부가 있는 **입력 목록**을 반환한다.
거래대금 상위 100종목 같은 별도의 선정 규칙을 끼워 넣지 않는다.
다음 항목은 모두 꺼진 상태다:

- `orders_enabled=false`
- `strategy_approved=false`
- `strategy_history_verified=false`

따라서 기존 매수 신호/주문 작업은 변경하지 않았다. 검증된 전략의 이력 길이, 분할/분배금 처리,
선정 규칙, 거래비용, 주문 시점을 동일하게 적용하는 다음 단계가 필요하다.
과거 가격이 아직 미수집이어도 일별 입력 표 자체는 준비될 수 있으므로 이 상태를 전략 준비 완료로 해석하면 안 된다.

## 설정과 확인

- `MARKET_DATA_DAILY_ENABLED=true`: 새 일별 예약만 활성화. `false`로 변경하면 예약 작업을 중지할 수 있다.
- `MARKET_DATA_DAILY_MAX_REQUESTS`: 기본 10000, 최대 20000.
- `MARKET_DATA_DAILY_START`: 기본 2026-09-01. 이어받는 동안 변경하지 않는다.
- 기존 `MARKET_DATA_REPOSITORY`, `MARKET_DATA_BRANCH`, `MARKET_DATA_REPO_TOKEN`, KIS 키를 재사용한다.
- 오래된 06:20 incremental용 `MARKET_DATA_PIPELINE_ENABLED`는 활성화하지 않는다.

Actions Summary에서 실행 기준일·가격 기준일·대상 종목 수·이번 조회/재사용 수를 확인한다.
첫 실제 예약 수집의 성공 여부는 실행 결과로 확인해야 하며, 코드 테스트 통과만으로 실제 전종목 적재 완료를 주장하지 않는다.
